# Iteration NNN — Concise scope title

## Goal

State the intended outcome and its boundary in one short paragraph.

## Added and updated

- Describe each material capability, public artifact, or user-visible behavior
  introduced or changed.
- Name significant files or components only when that improves traceability.

## Current capability

Describe what a user, operator, or integrating system can do now. Do not
describe planned behavior as if it already exists.

## Deliberately deferred

- List material capabilities that remain out of scope for this iteration.
- Keep limitations explicit when an API, integration, or action is not present.

## Validation

- List the checks actually run and their results.
- State an unavailable check plainly, including what remains to be run.

## Decisions

- Record enduring architecture, contract, ownership, or UX decisions that will
  help later work.

## Authoring notes

- Use the highest existing numeric `iteration-NNN.md` unless a new iteration is
  explicitly requested.
- Remove sections that genuinely do not apply rather than leaving placeholders.
- Update changelog entries for meaningful product, architecture, contract, or
  user-visible presentation changes; do not add entries for small fixes or
  routine internal maintenance.
