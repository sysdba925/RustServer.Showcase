# Iteration 107 — Normalize NetworkAccess guard in Control releases

## Problem

A fresh Control rollout failed to start the privileged NetworkAccess Helper.
Ubuntu's `nft -f` rejected guard rules on lines 7–8 with
`syntax error, unexpected junk`, which caused systemd to reject the
dependent Control startup and the Updater to roll back registration.

The rule strings checked into GitHub use LF, but Control releases are packaged
on Windows and the repository did not enforce LF checkout for `.nft` files.
A CR immediately after the final visible token is consistent with the
reported error location. The actual failed release archive was not inspected,
so the exact original file bytes have not been independently confirmed.

## Correction

- `RustServer.Control` adds `.gitattributes` for LF-terminated nftables
  resources and systemd unit files.
- Its publish script explicitly normalizes the copied nftables guard and helper
  unit to UTF-8 without BOM and LF-only newlines before creating the tarball.
- Publication rejects missing or empty NetworkAccess release resources.
- Added publishing documentation for inspecting the packaged guard and checking
  syntax with `nft -c -f`.

## Validation

- Verified the source guard on GitHub uses LF and that the published PowerShell
  path previously packaged assets without line-ending normalization.
- The archive generated by a new Windows publish and nft parser on Ubuntu still
  need to be tested before claiming the rollout is fixed.

## Decision

Preserve the application release boundary: Updater installs a verified Control
release; the release packager owns portable bytes in the archive. Bootstrap
does not acquire new NetworkAccess responsibilities.
