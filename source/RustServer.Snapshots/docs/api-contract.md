### POST `/api/snapshots`

Queues creation of a Fast or Consistent snapshot.

A Fast snapshot copies currently persisted runtime files directly into an archive without RCON. It can run while Rust is running, but unsaved changes may be absent and concurrent file writes can yield an inconsistent copy. A Consistent snapshot is accepted only when RustServer.Control reports that the server is stopped; this service never stops or starts it. Returns 202 Accepted with an operation identifier. Invalid input returns 400; an unsafe Consistent request returns 409 ServerMustBeStopped; invalid local storage configuration returns 500; unavailable Control status returns 502. Filesystem and archive failures are reported by the asynchronous operation.

### POST `/api/snapshots/{id}/restore`

Queues destructive restoration of a snapshot.

Restore replaces the configured server identity and Oxide data, config, plugins, and language directories from the snapshot archive. Rust must be stopped according to RustServer.Control; this service never changes its lifecycle. Returns 202 Accepted with an operation identifier, 404 Not Found for an absent snapshot, 409 ServerMustBeStopped if Rust is running, 500 for local storage/configuration errors, or 502 when Control status is unavailable.
